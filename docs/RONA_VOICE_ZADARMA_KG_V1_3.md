# RONA Voice — Kyrgyzstan +996 / Zadarma v1.3

## Decision

The target public voice number is a Kyrgyzstan DID (`+996`, Bishkek `0312`) obtained from Zadarma. The number is a transport endpoint only and never becomes an authoritative RONA identity.

## Target architecture

### Inbound

`PSTN -> +996 Zadarma DID -> Zadarma SIP URI -> OpenAI Realtime SIP -> rona-voice-zadarma-adapter -> fixed RONA AI role`

The Zadarma DID is routed to the OpenAI project SIP endpoint. The OpenAI `realtime.call.incoming` webhook is verified cryptographically by the adapter. The adapter additionally requires the inbound SIP metadata to contain the configured `CALLED_DID` and a Zadarma SIP host before it can create a trusted telephony binding.

### Outbound

`RONA authorized coordination record -> rona-voice-zadarma-adapter -> Twilio Calls API control leg -> authenticated Zadarma SIP egress -> PSTN destination -> OpenAI Realtime SIP bridge`

Twilio is used only as the programmable control/bridge leg for outbound calls. PSTN egress remains Zadarma SIP. The connected +996 DID must be the default Caller ID of the Zadarma SIP account. No outbound request can be created from an unaudited source record.

## Fixed role boundary

Allowed telephone roles:

- `OPERATIONS_DIRECTOR`
- `FINANCE`
- `LEGAL`
- `MARKET_ANALYST`
- `RAIL_LOGISTICS`

`SYSTEM_ADMIN` is excluded from voice routing.

External voice sessions are created with `tool_choice=none`. A phone number, Caller ID, email, spoken company name, SIP header, address-book match, or prior call history is never authoritative client identity and cannot create a Portal User, client binding, contract access, IAM grant, payment action, legal decision, or other authoritative mutation.

## Default security state

- recording: `DISABLED`
- transcript: `METADATA_ONLY`
- provider and AI activation: fail closed
- production calling: disabled until live acceptance gates pass
- internal communication generated by voice work: network coordination contour only
- internal email: prohibited except when processing a request that originated by email

## Runtime secrets

The following values belong only in protected server-side secrets and must never be pasted into chat, source control, logs, or client-facing LK:

### Required for inbound preparation

- `ZADARMA_API_KEY`
- `ZADARMA_API_SECRET`
- `ZADARMA_DID_E164`
- `OPENAI_API_KEY`
- `OPENAI_WEBHOOK_SECRET`
- `OPENAI_PROJECT_ID`

### Required for outbound calling

- `ZADARMA_SIP_USER`
- `ZADARMA_SIP_PASSWORD`
- `ZADARMA_SIP_OUTBOUND_HOST` (defaults to `sip.zadarma.com`)
- `TWILIO_ACCOUNT_SID`
- `TWILIO_AUTH_TOKEN`
- `TWILIO_FROM_E164` (must be a Twilio-allowed/verified caller identity)

### Acceptance-only allowlists

- `RONA_VOICE_TEST_CALLER_E164`
- `RONA_VOICE_TEST_CALLEE_E164`
- optional `RONA_VOICE_REALTIME_MODEL` (default `gpt-realtime-2.1`)

## Admin endpoints

- `GET /health` — public fail-closed service health
- `GET /admin/health` — authenticated ADMIN state/capability view
- `POST /admin/provider/prepare` — probes real Zadarma DID and OpenAI model; does not enable live calls
- `POST /admin/provider/route-openai` — routes the purchased DID to the OpenAI SIP endpoint and moves the gate only to `INBOUND_TEST`; production remains disabled
- `POST /admin/outbound/request` — requires ADMIN auth, a real non-QA coordination source, matching fixed role, explicit purpose and idempotency key
- `POST /openai/webhook` — verified OpenAI incoming-call webhook
- Twilio outbound callback endpoints — verified with `X-Twilio-Signature`

## Activation gates

1. `FOUNDATION`
2. `INBOUND_TEST`
3. `OUTBOUND_TEST`
4. `PRODUCTION_READY`

Provider preparation and routing never set `PRODUCTION_READY` automatically. Test calls are accepted only from the configured acceptance caller/callee while the corresponding test gate is active.

## External provisioning still required

The software cannot create or pay for a third-party telecom account without account credentials/payment/KYC authority. Before live acceptance, the organization must have an activated +996 DID, server-side API/SIP credentials, an OpenAI API project with an incoming-call webhook, and (for outbound) a Twilio account capable of placing the authenticated SIP call leg.
